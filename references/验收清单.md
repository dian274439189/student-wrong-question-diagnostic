# 验收清单（交付前逐条打勾）

> 对应技能 L6 呈现层。任何一条不通过，先修复再交付。
> v2.0（2026-11-12）：用户要求 7 项 → 9 项，交付前自检 8 项 → 10 项，脚本自检新增 audit 行。

## 一、用户 9 项要求逐条对照（v2.0）

| # | 要求 | 落点 | 检查方式 |
|---|---|---|---|
| 1 | 三色提取试卷错误题目 | 两份 Word 的题干黑、作答深蓝、批改／答案红 | 跑脚本的 `color_audit`，`000000 / 003399 / C00000` 三者齐全 |
| 2 | 提取所有错题 | 家长版第二、三节；学生版第一节 | 卷面红色扣分题数 = 判定表行数；满分题不混入错题；**INVALID 题不混入** |
| 3 | 一一对比、一眼看出错在哪 | 学生版双栏对照表＋红字「【就岔在这一步】」；家长版【错在哪】红字段 | 每题至少 1 个岔路口标记；一句话错在哪必须是红字加粗 |
| 4 | 错误原因＋错误思路与正确思路对比 | 对照表逐步骤对齐；家长版四维判定＋错因归类 | 每道题左列写的确实是学生原来的路子，不是编造的「典型错误」 |
| 5 | 正确思路与步骤、错误归因 | 家长版 steps 5–9 步＋五类错因；学生版口诀＋错因 | 正确解法以 L2.0 收敛答案为准，已独立验算且自洽 |
| 6 | 举一反三 | 每题 2–3 道变式，答案在文末 | 变式答案与题目分离；每题答案可举一例验证；INVALID 题不得出变式 |
| 7 | 知识点＋快速提升形式 | 知识点分布表、20 分钟四小块、5 分钟动作、复习排期 | 每条提升动作具体到「做什么、几分钟、练到什么程度」 |
| 8 | **题目本身是否正确（v2.0）** | 家长版「三·补」题面审查章节；学生版开头印错提示；L3 八列表「题面状态」列 | 三态计数齐全；`SUSPECT`/`INVALID` 三处可见；`INVALID` 不在逐题错题列表、变式、错因表中 |
| 9 | **标准答案交叉论证与正确率（v2.0）** | 家长版「三·补」答案收敛表；`accuracy_summary` | 六路记录或降级原因齐全；`CONTESTED` 不得标 `high`；正确率／覆盖率／收敛率三项同时给出；脚本 `audit checks` PASS |

## 二、交付前 10 项自检（v2.0）

- [ ] **双份齐全**：家长版三色诊断报告 ＋ 学生版大白话对照本，两份文件都存在且可打开。
- [ ] **三色落地**：遍历 `run.font.color.rgb`，三色都真实写入（不是只写在样式或 HTML 里）。
- [ ] **隐私扫描**：无姓名、班级、学号、学校、考号、座位号；家长版写「该生」，学生版写「我」。
- [ ] **答案隔离**：变式答案不在题目旁边；家长版标「家长保管」，学生版标「做完再看」。
- [ ] **语言口径**：学生版无未解释术语、无长定语从句、无 emoji、无「粗心」式空泛归因。
- [ ] **四张存疑清单**：识别存疑、判定存疑、题面存疑、答案源存疑，逐条写原因，不静默带过。
- [ ] **确认层**：八列判定表已给用户过目；未获「确认入库」前不写错题库；两个必填字段未默认填。
- [ ] **落盘路径**：成果写入 `--out` 指定目录（默认 `./output/<YYYY-MM-DD>`），路径可由用户配置。
- [ ] **题面审查（v2.0）**：六维与五视角已执行（红灯题强制五视角）；`SUSPECT`/`INVALID` 在家长版、学生版、八列表三处可见；`INVALID` 未入错题库、未出变式、未计入分母。
- [ ] **答案交叉论证（v2.0）**：六路分次独立执行且有独立裁决轮；机器验证通过或标注「无机器验证」；`CONTESTED` 未强行定案；正确率与覆盖率同时给出，未达门槛写「待裁定，样本不足不予计算」。

## 三、脚本自检输出判读

正常运行末尾应为 `RESULT: PASS | files: 2`，且两份都显示：

```
tri-color missing: none | privacy hits: none
```

v2.0 起，写入核验字段的数据还会输出一行：

```
audit checks: PASS | valid=5 suspect=1 invalid=1 | confirmed/high=6 contested=1 | accuracy=86% coverage=88% convergence=86%
```

使用 v1.0 数据（无核验字段）时显示 `audit checks: SKIPPED (v1.0 data)`，**属正常，不算失败**——黄金样例即属此类。

- 出现 `missing` → 检查题干／作答／答案三段是否都用了对应颜色的 `kv` 或 run。
- 出现 `privacy hits` → 定位命中文本，改写或删除；必要时用 `--forbidden` 追加本卷专属身份信息。
- 出现 `audit FAIL` → 按提示定位：状态值非法 / `INVALID` 混入逐题错题列表 / `pending` 计入分母 / 正确率算术不自洽 / 缺覆盖率收敛率。修复后重跑。
- 退出码 1 → 禁止交付，先修复。

## 四、换一套卷子的复跑验收

1. 复制 `templates/sample-exam.json`，改名后只替换 `meta`、汇总表、`parent_items`、`student_items`。
2. 跑 `python scripts/build_books.py --data <新JSON> --out <输出目录>`，确认 `RESULT: PASS`；填了核验字段的还要确认 `audit checks: PASS`。
3. 抽查 3 道题：题干与作答原文一致、正确答案与 **L2.0 收敛答案**一致、对照表岔路口标在真正走错的那一步；另抽查 1 道 `INVALID`/`SUSPECT` 题，确认三处提示齐全。
4. 让学生读其中一道题后复述「我错在哪、正确该怎么想」；能复述才算第 3 条要求「一眼看懂」通过。
5. 若脚本需要改代码才能适配新卷 → 说明模板／数据分离被破坏，回到 `references/数据契约.md` 修正数据结构。

## 五、不合格处置

| 现象 | 处置 |
|---|---|
| 手写认不清 | 标【识别存疑】或「需重拍」，不硬读；不得靠上下文补字 |
| 参考答案与独立论证不一致 | 并列两套解法标「待裁定」，写进答案源存疑，交用户／老师裁定；**不预设参考答案正确** |
| 题目本身出错／条件矛盾 | 标【题目有误】、剔除分母、双份 Word 提示；停止判该题，不改写题干、不自行补条件 |
| 多路答案收敛不了 | 标 `CONTESTED` / `pending`，写进答案源存疑，交用户裁定；禁止多数票定案 |
| 官方答案确认印错 | 以独立论证结果为准（须人工确认），写进答案源存疑并请老师确认 |
| 正确率高但覆盖率低 | 视同指标失真；按门槛写「待裁定，样本不足不予计算」，不得只报正确率 |
| 学生版读起来像家长报告 | 按 `references/白话改写规则.md` 重写，重点改句式与术语 |
| 只有一份 Word | 补跑 `--only` 指定缺失的那份，再合并验收 |
| 用户只想要一份 | 仍生成两份，回复里说明另一份可随时取用；不主动删 |
